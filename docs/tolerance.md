# 浏览器参考差分与公差说明

## 方法

每个场景在同一 320×240 视口内渲染两次：

- **参考图**：Chromium（Playwright headless，Chrome for Testing 159）对原生
  `<path>` 直接使用浏览器 SVG 引擎的 `stroke` 渲染。
- **候选图**：本库把描边扩展成**纯填充路径**（`fill` + `fill-rule="nonzero"`，
  无任何 `stroke`/`dash` 属性），再交给同一浏览器光栅化。

两图均在透明背景上用同一种近黑色绘制，用 `pngjs` 逐像素比较。像素比较的不是
alpha，而是“墨量覆盖度” `coverage = (1 - luminance) * alpha`，这样白色背景与
透明背景不会产生伪差异。

## 指标

| 指标 | 含义 |
| --- | --- |
| `mismatchPixels` | 两图覆盖度差值超过 `ALPHA_THRESHOLD=32/255` 的像素数 |
| `mismatchRatio` | 失配像素 / 画布总像素（320×240） |
| `meanAlphaDelta` | 全图平均覆盖度绝对差（0–255） |
| `maxBandPx` | 仅出现在一侧的边缘像素到另一侧边缘的最大距离（有界 6px 扫描） |
| `coverage ref/cand` | 两侧覆盖度大于 128 的像素总数 |

## 判定公差

```
mismatchRatio <= 0.006      # 失配像素不超过 0.6%
meanAlphaDelta <= 2.0       # 平均墨量差可忽略
maxBandPx      <= 1.6       # 边界位移控制在约 1.5 像素内
```

### 为什么是这些值

1. **抗锯齿边缘（亚像素噪声）**：浏览器对 1px 宽的边缘用约 2 个像素做线性
   coverage 过渡。两套几何即使数学上重合，光栅化顺序、多边形裁剪与扫描转换的
   细微差别也会在边缘产生 1 个像素、覆盖度 < 32 的抖动。`ALPHA_THRESHOLD=32`
   专门滤掉这类弱信号，剩余差异由 `meanAlphaDelta <= 2` 兜底。
2. **曲线扁平化误差**：三次贝塞尔/圆弧按容差 `flattenTolerance=0.2` 用户单位
   自适应细分，弦到曲线的偏差不超过 0.2 单位，叠加描边半宽后边界位移远小于
   1px。`maxBandPx <= 1.6` 允许一个扫描行的取整，同时足以捕获真正的几何错位
   （开发期真实 bug 通常产生 4–7px 的 band）。
3. **0.6% 失配上限**：对本测试的细描边场景，纯抗锯齿噪声的失配率约 0.1–0.2%；
   取 3 倍裕量到 0.6%，既不放宽到能放过结构性错误，又避免对光栅器实现差异过敏。

## 当前结果

见 `artifacts/render/diff-report.txt`。8 个场景全部通过，`maxBandPx <= 1`，失配率
最高 0.0014（非均匀缩放曲线，阈值 0.006），显著优于阈值。闭合虚线接缝、三角形
斜接、square 端帽、butt 零长度子路径等场景达到逐像素零差异；其余场景仅在抗锯齿
边缘有个位数到百余像素的弱覆盖抖动（`meanAlphaDelta <= 0.16`，阈值 2.0）。

## 与浏览器的已知行为分歧（已对齐而非忽略）

- **零长度子路径**：SVG 规范允许 round/square 端帽在零长度段上画点，但 Chrome/
  Skia 对长度小于约 0.25 用户单位的子路径直接跳过端帽。本库默认用
  `minSubpathLength: 0.25` 复刻该行为以通过浏览器差分；需要规范行为时设为 `0`。
- **斜接限制**：超过 `miter-limit` 时仅**外侧**回退为 bevel，内侧仍用斜接交点，
  与浏览器一致。
- **非均匀缩放**：先在用户坐标系构建完整描边轮廓，再对顶点应用 CTM。于是
  round 端帽在 `scale(2, 0.5)` 下变成椭圆，斜接尖落到变换后的偏移位置——这与
  SVG“描边随 CTM 变形”的语义一致。
